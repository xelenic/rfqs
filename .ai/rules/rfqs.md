# Rfqs

## Sourcing has no Return to Senior Operations
Since 2026-10-12, only Admin can send a Sourcing part back to Senior Operations (the 'sourcing_to_ops' kind of _complete_button, RfqController::returnSeniorOps()), recorded as the part's member. Every spot that shows it, and the controller, gate on User::canSendSourcingPartsBackToSeniorOps(). Don't show it to Sourcing again without the business asking.

## RFQ progress chart: HTML cards and SVG lines, no ECharts
Since 2026-10-16, renderRfqProgressChart (public/js/admin.js) draws the RFQ page's Progress chart itself instead of using ECharts. Columns follow tree depth, there is one row per lane, and each parent is centred on its children. Every node is an HTML card (.pc-node) with a round picture overlapping its left edge, connected by SVG curves. Each node in #rfq-progress-data (built in show.blade.php) carries: name, role, step, rfq_number, meta[0..1], state (done/current/pending/returned), icon (from $stepTabs) and person. person is null for nobody, ['masked' => true] when the name must stay hidden (show a lock), or name/photo/initial. Masking stays server-side, so hidden names never reach the page. Build card text with textContent, never innerHTML.

## Sourcing's My Pending RFQs: three tabs
Since 2026-10-16, a Sourcing member's My Pending RFQs has three tabs, part by part. **Pending for Sourcing** ($rfqs, data-de-tab="todo", the default) lists parts still with them (completed_at and returned_at null) and parts Data Entry sent back to finalize (RfqAssignment::whereAwaitingFinalize()). **With Data Entry** (?tab=with-data-entry, $withDataEntryRfqs) lists parts with completed_at set and data_entry_completed_at null; it shows Not started / In progress / Paused and whom it was assigned to, but never who in Data Entry started it. **Finalized** (?tab=finalized, $finalizedRfqs) lists finalized parts on Pending RFQs, with RfqAssignment::stageAfterFinalize(). Data Entry returns stay on Returns. Each tab has its own paginator and count ($sourcingCounts). The open tab is kept in ?tab= via data-de-tab / data-tab-default and #deTabInput. Keep the controller queries, the row loops' @continue checks and the sidebar badge (Pending for Sourcing = open + Rfq::awaitingFinalizeCount()) in step. Admin's _sourcing_overview has a single list.

## Senior Operations' Approve verifies line items first (_senior_ops_approve_modal)
Since 2026-10-19, every Senior Operations Approve opens _senior_ops_approve_modal through _senior_ops_approve_button; never a plain form. That covers a part on the Review list (approvePart) and the whole RFQ on the list's fallback row and the RFQ page. For each part it approves, the popup shows Line Items to Add, Line Items Added and Difference, read only, from RfqAssignment::lineItemsCheck(), and asks for Actual Line Items (actual_line_items[part]). RfqController::verifiedLineItems() requires one for every part, a whole number from 0 to MAX_DATA_ENTRIES, for approveSeniorOpsPart() and completeSeniorOpsReview() (Rfq::partsAwaitingSeniorOpsApproval()). It's kept as rfq_user.verified_line_items. Read it with verifiedLineItems(): returns are not cleared, so the value only counts while the part is Senior-Ops-approved. Pass the part as approvePart, never $part, which show.blade.php already uses.

## Add RFQ: WC is fixed, only the four digits are typed
Since 2026-10-20, while Settings → WC Validation is on (Setting::wcFormatRequired()), the Add RFQ form's WC Number has "WC" fixed in an input-group, and the field takes only four digits. admin.js (.js-wc-digits) strips anything else, so a pasted "WC0123" becomes "0123". The field has no maxlength, because a maxlength would cut a paste before the script strips it. RfqController::store() calls wcNumberChecked(..., digitsOnly: true), which saves "0123" as WC0123 and still accepts a whole "WC0123". The Edit form keeps the whole WC0000 field, so older numbers can stay. With the setting off, both forms are free text.

## @mentions: all active staff, with roles and pictures
Since 2026-10-20, anyone active can be @mentioned in an RFQ comment: RfqComment::mentionableUsers(), looked up once per request and kept on the request's attributes, not once(). The dropdown reads RfqComment::mentionDirectory() from show.blade.php's #rfq-mention-users JSON (id, name, role, avatar, initial; json_encode with the JSON_HEX flags). admin.js builds each item with the person's photo or initial and their roles, and matches what's typed against name or role. bodyWithMentions() highlights in one regex pass, longest names first and whole names only. Pass it mentionableUsers(), never a role's members, so highlighting matches the dropdown and the closed-RFQ mention messages.

## Sourcing and Data Entry see only their own part of an RFQ's timeline
Since 2026-10-20, the RFQ page renders Rfq::activityTimelineFor(auth()->user()), never activityTimeline() directly. Someone in Sourcing and/or Data Entry with no other role (User::seesOnlySourcingAndDataEntryTimeline()) gets three things. Lifecycle events: only Rfq::SOURCING_AND_DATA_ENTRY_TIMELINE_TYPES. Action comments: only those whose author is in Sourcing or Data Entry; plain comments and replies stay, since they're the shared discussion (RfqComment::isForSourcingAndDataEntry()). Alerts: only those sent to someone in Sourcing or Data Entry. No other role's reviews, approvals, rejections, holds, reassignments or GM Assistant actions. The header's comment count counts what they see. _rfq_detail_modal's thread applies the same comment filter. Everyone else, Admin and anyone holding another role included, sees everything.

## Closed RFQs: no created or closed details for Sourcing and Data Entry
Since 2026-10-20, someone in Sourcing and/or Data Entry alone (User::seesOnlySourcingAndDataEntryTimeline()) doesn't see when a closed RFQ was made or closed, by whom, or its quotation number. On the Closed RFQs list ($hidesCreatedAndClosed in index.blade.php), the Created and Closed columns are left out: _rfq_row takes showCreated and showClosed, and _closed_part_rows takes showCreatedAndClosed, with the colspan adjusted. On a closed RFQ's page, the details card leaves out Created by, Created and Quotation number. Their step tabs and timeline already leave out the Created and Closed steps. Everyone else, and an open RFQ, are unchanged.

## Head of BD's Approve finalizes line items, which drive GM Assistant's target
Since 2026-10-20, every Head of Business Development Approve opens _head_of_bd_approve_modal through _head_of_bd_approve_button ($approvePart for a part, or null for the whole RFQ). The popup shows to add, added and Senior Ops' verified count read only, and asks for Finalized Line Items (finalized_line_items[part]). RfqController::finalizedLineItems() requires one for every part (it shares lineItemsGiven() with the Senior Ops check). They're kept as rfq_user.finalized_line_items; read them with finalizedLineItems(), which is null unless the part is Head-approved, since returns don't clear the column. Rfq::gmAssistantLineItemsFor() prefers them (source 'finalized'), and gmAssistantTargetBreakdown() then always goes per line item, even with Settings' per-line-item switch off, as Data Entry's line items to add do. Both line-item popups are .js-line-items-modal with data-field; admin.js fills any read-only box by its data-value key.
